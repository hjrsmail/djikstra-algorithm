Mengapa Bellman–Ford memeriksa ke belakang?

Ruas dua arah Rektorat–Kantin memiliki bobot 200 pada kedua arah. Namun kandidat jaraknya berbeda:

Rektorat → Kantin: 0 + 200 = 200
Kantin → Rektorat: 200 + 200 = 400

Biaya menuju pangkal sisi berbeda. Kandidat balik 400 tidak memperbaiki jarak Rektorat yang sudah 0. Bobot sisi sama, tetapi total biaya dari sumber berbeda.

Bellman–Ford memindai kedua arah untuk menyebarkan perbaikan sampai stabil. Panah animasi menunjukkan arah pemeriksaan, bukan arah perjalanan pengguna.

Bagaimana A* mengarahkan pencarian?

f(v) = g(v) + h(v)

g: biaya dari sumber; h: perkiraan sisa; f: prioritas. Dijkstra hanya memilih berdasarkan g.

Ke Parkiran, h = [700, 600, 450, 500, 200, 0]. Setelah Kantin diproses, f(Kelas) = 500 + 200 = 700; f(Laboratorium) = 500 + 450 = 950. A* memilih Kelas lebih dahulu.

h berasal dari koordinat ilustratif x = [0,100,250,200,500,700], bukan posisi SVG. h(u) ≤ w(u,v)+h(v) dan h(t)=0 diperiksa pada semua ruas. Jika h=0, prioritas A* sama dengan Dijkstra [9, 10].

Catatan pembicara

Gunakan kedua pembanding untuk menjelaskan Dijkstra. Jangan menyatakan A* selalu lebih cepat atau Bellman–Ford selalu lebih lambat. Tekankan bobot ruas dibanding total biaya dari sumber.

04 · Hubungan teori dan kode

Empat bagian inti program Dijkstra

d menyimpan biaya dari sumber, done menandai jarak final, dan prev menyimpan pendahulu rute.

1 · Inisialisasi
d[sumber] = 0

Lokasi awal berbiaya nol; simpul lain belum diketahui sehingga diisi ∞.

2 · Pilih minimum
minimum d, belum final

Pilih total biaya terkecil dari sumber, bukan bobot satu sisi terkecil.

3 · Finalkan
done[u] = True

Bobot non-negatif menjamin jarak u tidak perlu diturunkan lagi.

4 · Relaxation
d[u] + w < d[v]

Jika kandidat lebih murah, ubah jarak v dan prev[v] menjadi u.

Program kampus yang dapat dijalankan

Buka kode Python lengkap dan singkat 
from math import inf

def dijkstra(graf, sumber, tujuan):
    n = len(graf)
    d = [inf] * n
    prev = [None] * n
    done = [False] * n
    d[sumber] = 0
    for _ in range(n):
        u = None
        for v in range(n):
            if not done[v] and (u is None or d[v] < d[u]):
                u = v
        if u is None or d[u] == inf:
            break
        done[u] = True
        if u == tujuan:
            break
        for v, w in graf[u]:
            if not done[v] and d[u] + w < d[v]:
                d[v] = d[u] + w
                prev[v] = u
    rute, v = [], tujuan
    while v is not None and d[tujuan] != inf:
        rute.append(v)
        if v == sumber:
            break
        v = prev[v]
    return d[tujuan], rute[::-1]

nama = ["Rektorat", "Perpustakaan", "Laboratorium",
        "Kantin", "Kelas", "Parkiran"]
graf = [[] for _ in nama]
for u, v, w in [(0,1,400),(1,2,300),(0,2,500),(0,3,200),
                 (3,4,300),(2,4,400),(3,5,600),(4,5,200)]:
    graf[u].append((v, w))
    graf[v].append((u, w))
jarak, rute = dijkstra(graf, 0, 5)
print("Rute:", " → ".join(nama[v] for v in rute))
print("Jarak:", jarak, "meter ilustratif")

05 · Analisis Dijkstra

Mengapa versi linear memerlukan Θ(n² + m)?

n adalah jumlah simpul; m adalah jumlah sisi tidak berarah. Analisis berikut untuk graf terhubung dan keluaran semua jarak.

Memilih minimum

n × n

n pemilihan, masing-masing memindai n posisi. Total n² pemeriksaan posisi.

Memeriksa tetangga

2m

Setiap ruas dua arah tersimpan dua kali. Seluruh adjacency list dibaca sekali.

Ruang bantu

O(n)

Array d, prev, dan done. Ruang masukan adjacency list adalah Θ(n + m).

Kesimpulan biaya

Θ(n² + m) → Θ(n²)

Pada graf sederhana, m = O(n²). Graf eksperimen memiliki m = 3n, sehingga pemilihan minimum mendominasi.

Binary heap dapat memberi O((n + m) log n), tetapi varian heap tidak diukur dalam laporan. Fibonacci heap memberikan batas O(m + n log n) secara teoretis [12].

Batas analisis

Sumber terisolasi Θ(n), inisialisasi dan pemindaian terbatas
Worst case linear O(n² + m)
Satu tujuan O(n + rn + q)

r: simpul yang dipilih; q: entri tetangga diperiksa sebelum berhenti. Average-case complexity memerlukan distribusi masukan; rata-rata runtime pengulangan bukan average-case complexity.

Invariant: alasan jarak boleh difinalkan

Setiap simpul yang sudah dipilih memiliki jarak optimum. Di antara simpul yang belum final, u mempunyai estimasi minimum. Jalur alternatif melalui simpul lain tidak dapat menurunkan biaya menuju u dengan hanya menambahkan bobot non-negatif [1, 4].

Catatan pembicara

Pisahkan runtime dalam mikrodetik atau milidetik dari kompleksitas tanpa satuan. Sebutkan versi linear setiap kali membahas Θ(n²).

08 · Pesan akhir

Dijkstra memberi keputusan yang jelas pada bobot non-negatif

Hasil utama

  • Rute kampus: Rektorat–Kantin–Kelas–Parkiran, biaya 700.
  • Jarak aman difinalkan setelah simpul minimum dipilih.
  • Relaxation memperbaiki jarak sementara serta pendahulunya.
  • Versi linear memerlukan Θ(n² + m) pada graf terhubung.

Pelajaran dari pembanding

Bellman–Ford memperlihatkan bahwa seluruh sisi dapat diperiksa berulang tanpa finalisasi greedy.

A* memperlihatkan bahwa heuristic yang sah dapat mengurangi simpul yang dipilih, tetapi juga menambah pekerjaan.

Hasil runtime bergantung pada implementasi, graf, keluaran yang diminta, dan lingkungan pengujian.

Batas kajian dan pengembangan

Graf kampus bersifat ilustratif. Eksperimen SSSP memakai satu graf per ukuran dan lima pengulangan; benchmark kampus hanya satu pasangan sumber–tujuan. Varian heap belum diukur. Pengembangan Dijkstra dapat menguji banyak seed, kepadatan graf berbeda, serta varian heap dengan tugas dan masukan yang setara [11, 12].

Catatan pembicara

Akhiri pada Dijkstra. Sebutkan hasil rute, alasan benar, dan biaya versi linear. Kedua pembanding memberi konteks, bukan menggantikan objek utama pembahasan.
